# Komet для Windows 10 Mobile

Предварительный нативный порт Komet на C++/WinRT и UWP, ARM32. Исходный проект:
[KometTeam/Komet](https://github.com/KometTeam/Komet), ревизия
`7bbb73bd2c05877e48b37f6ec6f096471a341404` (0.5.19).
Код Flutter оставлен в корне репозитория; реализация для телефона находится в `w10m/`.

## Статус

Версия порта — `0.2.6.0`, пакет `dist/Komet.W10M_0.2.6.0_ARM.appx` для Windows 10 Mobile
1703/1709, минимум **10.0.15063.0**. Внешние пакеты VCLibs и .NET не нужны.

Это **не полный перенос функций Komet**. Вход в аккаунт, отображение интерфейса
и переписка на настоящем телефоне пока не проверены полностью. Современный
сервер MAX может изменить протокол или отклонить устройство; наличие кода
функции не означает, что её работа уже подтверждена с реальным аккаунтом.

В 0.2.6 фото и обложки видео занимают область прямо в сообщении. Встроенные
previewData (MessagePack binary, массив байт, data URI и бинарные данные после JSON-кэша) показываются сразу,
затем фотография автоматически заменяется полной версией. Вместо большой
кнопки загрузки — индикатор поверх изображения; при ошибке небольшая подпись
и повтор по нажатию на превью. Видео запускается поверх обложки и воспроизводится
в той же области. «Открыть / сохранить» для видео убрано из тела сообщения;
сохранение остаётся в меню сообщения.

Изображения декодируются в BGRA через Windows.Graphics.Imaging, включая EXIF
и premultiplied alpha, затем передаются в WriteableBitmap. WebP по-прежнему
декодируется встроенной библиотекой. Это проверено на синтетических JPEG, PNG,
WebP, в том числе на повороте EXIF и прозрачности; реальные CDN на телефоне
пока не проверены. Последняя ошибка HTTP/декодирования/отображения сохраняется
в настройках без URL, токенов и содержимого изображения.

У контактов с именем в кэше, но без URL аватара, запрашивается CONTACT_INFO;
запросы идут пакетами до 100, диалоги в приоритете. Пустое основное поле URL
больше не скрывает запасное. Фото использует photoToken, если рядом присутствует
пустой token. Ссылки, не загрузившиеся из кэша, удаляются для повторного получения.
Эти изменения не подтверждают работу конкретного CDN на W10M: если загрузка
не удалась, точная причина видна в диагностике изображений.

В 0.2.5 добавлен экран загрузки: без сохранённого токена открывается вход,
с аккаунтом — список чатов из кэша и восстановление соединения. Повторная
активация существующего окна больше не создаёт повторно тот же XAML-интерфейс.
После возврата сбрасываются флаги старой попытки переподключения.

Избранное (chatId=0) всегда доступно первым пунктом списка и отдельной командой;
ноль больше не считается отсутствием открытой переписки. История, отправка,
обновления, заголовок и возврат из профиля используют тот же путь, что и у других
чатов. Серверные сообщения отправляются в chatId=0, как в оригинальном Komet.

Присутствие дополнительно запрашивается через CONTACT_PRESENCE раз в 30 секунд.
В диалогах показываются «в сети», «не в сети»/последнее посещение или «статус не
указан», если сервер не передал данные. У исходящих сообщений — «Отправлено»
и «Прочитано» по participants.mark и NOTIF_MARK; в группе «Прочитано» означает
прочтение хотя бы одним другим участником. Прочтение собственного аккаунта
не выдаётся за прочтение собеседником. Открытая история отмечается прочитанной,
когда пользователь находится внизу; настройка anti-read сохраняется.

Картинки загружаются по HTTPS отдельным загрузчиком с тайм-аутами, очередью
до двух запросов, кэшем до 8 МБ и программным декодером WebP 1.6.0. Поддержка
WebP не зависит от кодеков W10M. При ошибке фото есть кнопка повтора, а причина
попадает в журнал. Подписчики одной загрузки больше не теряются при обновлении
сообщений. Видео показывает превью, если оно есть в данных сервера, и выбирает
доступный MP4, включая 240p/144p; воспроизведение зависит от кодеков телефона.
На панели чатов доступен «Профиль»: имя, фамилия, выбор фотографии; ответ
сервера обновляет и профиль, и запись собственного контакта в кэше.

Фоновая работа реализована через in-process ApplicationTrigger, SocketActivityTrigger
и системный socket broker. При приостановке UI-сессия закрывается; фоновая задача
авторизует отдельный TLS-сокет с interactive=false и передаёт его Windows.
В контексте сохраняются sequence number и незавершённый входящий пакет.
SocketActivityTrigger обрабатывает сообщения и keepalive, затем возвращает сокет
брокеру. Есть резервная TimeTrigger-задача с периодом не менее 15 минут. При
возврате на экран фоновый сокет освобождается, передний сеанс восстанавливается.
Для QR/веб-профиля используется сохранённый транспорт и периодическая проверка
(TimeTrigger, не чаще 15 минут), без передачи WebSocket брокеру.
Уведомления создаются через ToastNotificationManager; повторные сообщения и
сообщения самого пользователя отфильтровываются. В настройках есть отдельные
переключатели фона, уведомлений и текста превью, статус и повторная регистрация.

Это не WNS-push и не гарантия постоянной работы: Windows управляет лимитами,
экономией заряда и разрешениями фоновых задач. На ПК проверены компиляция и
протокол; передачу реального сокета брокеру, пробуждение с погашенным экраном,
уведомления и воспроизведение медиа требуется проверить на телефоне. Если фон
запрещён, состояние видно в настройках. При работе фоновой задачи ОС может
отменить её; незавершённый сокет закрывается.

Новые тесты: WebP → BMP с цветом/альфой и масштабированием, повреждённые
изображения, отметки прочтения и монотонность, Избранное с ID=0, сохранение
частичного пакета при передаче сокета на каждой границе кадра. Все фикстуры
вымышленные. Регистрация и вызов socket broker на самом W10M пока не проверены.

В 0.2.4 вложения выбираются через маленькую скрепку слева от поля ввода:
файл, фото, камера, аудиофайл и стикер. В строке сообщения остаётся кнопка
отправки, переход в конец доступен в меню переписки. Заголовок учитывает
системную строку состояния телефона. У аватарок отдельные слои фона, буквы
и фото: буква остаётся видимой до успешной загрузки изображения.

У аудио, голосовых и видео есть Play/Pause прямо в сообщении. Для Ogg/Opus
включены статические libopus 1.6.1, opusfile 0.12 и libogg 1.3.5; голосовое
скачивается по HTTPS и декодируется в локальный WAV потоком, затем играет
через MediaElement. Ограничения: входной аудиофайл до 16 МБ, длительность
до 30 минут. Видео использует кодеки ОС. Запись голосовых не реализована.
Неизменённые сообщения сохраняют свои элементы UI при обновлении истории,
чтобы обновления не пересоздавали проигрыватель.

Удалён ложный разрыв через 45 секунд без входящих пакетов: ping не обязан
иметь отдельный ответ. Тайм-аут одного запроса больше не закрывает весь
сокет; реальные ошибки транспорта по-прежнему запускают переподключение.
Ping продолжается во время загрузок. После восстановления соединения
не запускается блокирующая перезагрузка истории. При нажатии «Отправить»
без связи приложение восстанавливает её и отправляет текст, если пользователь
не изменил его и остался в том же чате и аккаунте; выбор вложения также
продолжается после восстановления. Отправка файла и сообщения не повторяется
автоматически, если подтверждение уже отправленного запроса не пришло.

Проверены синтетические mono/stereo Ogg Opus → WAV, длительность, ненулевая
амплитуда и отклонение повреждённых данных. Loopback WebSocket-тест проверяет
46 секунд тишины, ping без ответа, тайм-аут запроса и успешный следующий запрос
по тому же сокету: `./w10m/tools/test.ps1 -Session -Network`.
На телефоне с авторизованным аккаунтом эти изменения ещё нужно проверить.

В 0.2.3 исправлена вёрстка списка чатов: аватар и текст находятся в отдельных
колонках, фотографии обрезаются кругом, при ошибке загрузки остаётся буква (исправлено в 0.2.4).
Над полем ввода всегда видны «Файл», «Фото», «Аудио» и «Вниз»; «Аудио»
отправляет выбранный аудиофайл как файловое вложение, запись голоса пока отсутствует.
Загрузка истории больше не отключает прокрутку. При подгрузке старых сообщений
сохраняется положение, фоновое обновление не сбрасывает уже загруженную историю
и не перемещает читающего старые сообщения к концу. Проверка входящих ответов в этой версии приводила к ложным разрывам;
она исправлена в 0.2.4.
Проверка на реальном телефоне с авторизованным аккаунтом остаётся необходимой.

В 0.2.2 в интерфейсе появились аватарки: круглое фото в списке чатов
и в шапке переписки (для диалогов — аватар контакта из CONTACT_INFO,
для групп — `baseIconUrl` чата), при отсутствии картинки — буква имени
на акцентном фоне. Под заголовком переписки видно статус присутствия
(«в сети» или «был(а) в сети» из LOGIN-словаря `presence` и push-уведомлений
NOTIF_PRESENCE), а нажатие на шапку открывает профиль собеседника
или сведения о чате. Аудио воспроизводится прямо в сообщении
через MediaElement для форматов, которые декодирует Windows (MP3);
голосовые сообщения MAX хранятся в OGG/Opus — в 0.2.4 для них добавлен
собственный декодер.

В 0.2.1 приложения сами восстанавливают соединение: ping отправляется
без ожидания ответа, как в Kolibri, а при обрыве соединения фоновый поток
переподключается к MAX, пока сохранён токен. Восстановление не блокирует
интерфейс и не повторяет попытки чаще, чем раз в 30–150 секунд,
поэтому постоянные обрывы не сопровождаются циклом «подключение
к MAX» на экране. Кнопка «Назад» больше не возвращает на экран входа
при обрыве: пока есть сохранённый аккаунт, она ведёт к списку чатов.
Фотографии и стикеры показывает прямо в переписке, а имена собеседников
подгружаются через CONTACT_INFO для участников диалогов и авторов сообщений,
включая профиль совместимости.

В 0.2 исправлен путь входа по коду. В 0.1 использовалась веб-сессия без поля
`mode`, которое основной Komet добавляет к `AUTH_REQUEST`. Теперь вход по коду
использует постоянный TLS-сокет, основной профиль совместимости Komet, серверный
`callsSeed` и 96-байтный fingerprint из трёх SHA-256. Поле `chatCacheFingerprint`
также передаётся при LOGIN. Транспорт проверен без авторизации, но успешная
пользователь подтвердил получение кода на телефоне в 0.2.0.0. Вход после ввода
кода завершился серверной ошибкой `[internal]`; её точный этап старая сборка
не показывала, поэтому успешный вход ещё не подтверждён.

В 0.2.0.1 основной сокет переведён на `api2.oneme.ru`, как в Komet; параметры
первого LOGIN приведены к оригиналу (`chatsSync=-1`, `presenceSync=-1`, без
лишних веб-полей). Сохранён профиль из AUTH и поддерживаются альтернативные
формы account ID. Подтверждённый токен сохраняется до загрузки списка чатов;
есть «Повторить загрузку аккаунта». Код очищается от пробелов и дефисов,
а ошибка теперь показывает этап: проверка кода или загрузка аккаунта.

Если вход запрашивает код, используйте новый код из текущего запроса.
Сохранённый аккаунт при обновлении 0.2.4 остаётся на месте.

Сообщение «Проверка не пройдена» не является подтверждением отправки SMS.
Теперь отображается ключ ошибки сервера, если он присутствует; положительный
ответ тоже не обозначается как гарантированная доставка. Повторная отправка
использует настоящий `RESEND` в существующей сессии после паузы не менее 30 секунд.

В реализации есть (подробный статус — в [FEATURES.md](FEATURES.md)):

- Нативные экраны UWP с темой и акцентом Windows, системными шрифтами,
  нижней панелью команд, прокруткой и аппаратной кнопкой «Назад».
- Вход по коду, QR-коду и паролю двухэтапной проверки; регистрация профиля;
  несколько сохранённых аккаунтов с переключением.
  Способ доставки кода выбирает сервер. Для QR требуется MAX на другом устройстве.
- Список чатов, поиск по загруженным чатам и ручная загрузка следующих страниц.
- Настоящие имена диалогов и авторов сообщений через CONTACT_INFO.
- Текстовая история порциями по 50 сообщений, максимум 500 в открытом чате.
- Отправка текста с подтверждением сервера; при тайм-ауте текст остаётся в поле.
- Ответы, пересылка, копирование, редактирование, удаление, реакции и закрепление.
- Контакты, поиск по телефону и глобальный поиск, блокировка, профиль и сессии.
- Создание групп/каналов, вступление по ссылке, сведения о чате и участники.
- Файлы: выбор, потоковая загрузка, получение ссылки и сохранение на телефон.
- Фотографии: выбор или системная камера, загрузка, просмотр, аватар профиля,
  а также показ фотографий и стикеров прямо в переписке.
- Просмотр видео/аудио через системный MediaElement при поддержке формата ОС.
- Выбор стикеров, создание и участие в опросах, отложенная отправка текста.
- Автоматическое переподлючение после обрыва связи, пока сохранён токен.
- Обновление открытого приложения по событиям сервера. Во время набора текста
  автоматическое обновление откладывается; команда «Обновить» доступна вручную.
- Сохранение токена в Windows PasswordVault и постоянного ID установки
  в LocalSettings. Номера, коды, пароли и сообщения не записываются в журналы.
- Переподключение после возобновления приложения; зашифрованное локальное
  сохранение чатов, контактов, истории и черновиков через DataProtectionProvider.
  Сохраняются до 10 переписок по 200 сообщений, в открытом чате — до 500.

Полный перенос **не завершён**. Пока отсутствуют голосовые/видеозвонки,
запись голосовых и видеокружков, специальная отправка видео чанками,
WNS-push (socket broker добавлен в 0.2.5), истории, мини-приложения, Digital ID, папки,
дополнительное шифрование Komet и полный набор тонких настроек. Анимированные
стикеры не воспроизводятся. Локальная история не является полной SQLite-базой
оригинала. Локальный выход удаляет токен текущего аккаунта и кэш;
завершить другие серверные сессии можно на экране устройств.

Проверена готовая ARM32-библиотека Microsoft `mrwebrtc_uwp` 2.0.2. Её
[проект требует минимум build 17763](https://github.com/microsoft/MixedReality-WebRTC/blob/v2.0.2/tools/build/mrwebrtc/uwp/mrwebrtc-uwp.vcxproj),
поэтому она не включена в пакет для W10M 15063/15254. Для звонков нужна
другая совместимая сборка WebRTC и отдельная интеграция SDP/ICE и сигналинга MAX.

## Установка на телефон

1. Скопировать `Komet.W10M.Development.cer` и `Komet.W10M_0.2.6.0_ARM.appx`
   из `dist/` на телефон с подходящей версией Windows 10 Mobile.
2. Для установки этого тестового пакета телефон должен разрешать установку
   приложений разработчика. Установить приложенный публичный сертификат,
   затем открыть APPX в проводнике телефона. Альтернатива — установка APPX
   через уже настроенный Windows Device Portal или штатные средства развёртывания.
3. Если уже установлена 0.1 или 0.2, обновить поверх неё: имя пакета, издатель
   и ключ подписи сохранены. Запустить Komet, запросить код или выбрать QR-вход.

Сертификат самоподписанный, для тестовой сборки. Скрипт подписи не устанавливает
его в доверенные хранилища компьютера. Закрытый ключ остаётся в `.private/`
и не включается в архивы. Если возникает ошибка установки, для диагностики
нужны её полный код, модель телефона и номер сборки ОС.

## Что проверено на ПК

- Компиляция ARM32 и упаковка с проверкой манифеста MakeAppx.
- PE32 ARM Thumb-2, AppContainer, таблица импортов, отсутствие внешнего CRT.
- Хеши блоков APPX и криптографическая проверка CMS-подписи.
- 31 проверка протокола и 20 000 проб повреждённых данных: MessagePack,
  64-битные ID, числовые ключи карт, LZ4 block/frame, Zstandard, обрывы,
  ограничения размера/вложенности и нормализация необязательных полей.
- Fingerprint проверен по независимому SHA-256-вектору, включая отрицательный
  int64 seed, порядок digest и бинарный тип поля MessagePack.
- Успешные неавторизованные SESSION_INIT и PING с настоящим MAX через тот же
  `Session.h`, собранный для x64: WebSocket и основной TLS-сокет к `api2.oneme.ru`.
  Наличие `callsSeed` проверено. Учётные данные пользователя не использовались,
  запросы SMS в тестах не отправлялись.
- Компиляция настольного UWP-предпросмотра до добавления QR-входа. Запуск
  предпросмотра не состоялся: регистрация пакета отклонена политикой Windows,
  запрещающей загрузку неопубликованных приложений. Визуальная проверка не выполнена.

Для веб-сокета TLS использует системное доверие Windows. У основного `api2`
применяется тот же встроенный корень Минцифры, что у Komet/Kolibri. Перед
передачей данных проверяются цепочка до этого корня, срок, назначение SSL-сервера
и DNS-имя. Корень используется только в памяти приложения, без установки в
системные хранилища. Доверие произвольным сертификатам не разрешено.

## Сборка

Нужны Windows x64, PowerShell, Python 3 с Pillow, Windows SDK 10.0.26100.0
с заголовками, WinMD, MakeAppx и SignTool, а также ARM32-инструменты:

- MSVC `14.44.35207`, компилятор HostX64/ARM, ARM Store CRT и заголовки.
- ARM32-библиотеки Windows SDK `10.0.22621.0`.
- C++/WinRT `2.0.230706.1`. Новые версии генератора не подходят для ARM32.

На этом компьютере подходящий набор уже находится в
`D:\Win10M\lumiatunnel\.tools`. Скрипт сборки по умолчанию использует его;
для другого расположения нужен параметр `-ToolchainRoot`. Ожидаемые пути внутри:

```text
msvc-arm/VC/Tools/MSVC/14.44.35207/bin/Hostx64/arm/cl.exe
msvc-arm/VC/Tools/MSVC/14.44.35207/include/
msvc-arm/VC/Tools/MSVC/14.44.35207/lib/arm/store/
sdk-arm/extracted/Windows Kits/10/Lib/10.0.22621.0/um/arm/
sdk-arm/extracted/Windows Kits/10/Lib/10.0.22621.0/ucrt/arm/
cppwinrt/bin/cppwinrt.exe
```

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File w10m\tools\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File w10m\tools\sign.ps1
python w10m\tools\verify-package.py w10m\dist\Komet.W10M_0.2.6.0_ARM.appx
powershell -NoProfile -ExecutionPolicy Bypass -File w10m\tools\test.ps1 -Network
```

Для тестов нужен MSVC x64; `test.ps1` принимает `-VcRoot`, `-SdkRoot`,
`-SdkVersion`. Без `-Network` тесты не обращаются в сеть.
`preview.ps1` компилирует и регистрирует отдельное x64-приложение
`Komet.W10M.Preview`; для запуска требуется разрешённое развёртывание
пакетов разработчика. Этот скрипт не меняет политики Windows.

Генератор WinRT использует метаданные установленного SDK; минимум в манифесте
не является доказательством совместимости всех API с телефоном. Проверка
на устройстве остаётся обязательным следующим этапом.

## Основа переноса и лицензии

У Flutter нет цели сборки Windows 10 Mobile/ARM32 в
[поддерживаемых платформах](https://docs.flutter.dev/reference/supported-platforms).
Поэтому интерфейс и транспорт реализованы отдельно на UWP.
Использован системный [MessageWebSocket](https://learn.microsoft.com/en-us/uwp/api/windows.networking.sockets.messagewebsocket).

Формат пакетов и LZ4 взяты за основу из `lib/core/webpush/max_web_protocol.dart`,
параметры соединения — из `max_web_socket.dart` и `backend/api.dart`, авторизация — из `account.dart`
и `web_push_service.dart`, история и отправка — из `messages.dart`.
Код портирования распространяется по GPL-3.0, см. корневой `LICENSE`.

Встроены [nlohmann/json 3.11.3](https://github.com/nlohmann/json/tree/v3.11.3)
и [QR Code generator 1.8.0, Project Nayuki](https://github.com/nayuki/QR-Code-generator/tree/v1.8.0),
обе библиотеки по MIT. Тексты лицензий сохранены в `third_party/` и пакете.
Также используются LZ4 1.10.0 (BSD-2-Clause) и Zstandard 1.5.7 (BSD-3-Clause).
Корневые сертификаты взяты из Kolibri, текст MIT-лицензии сохранён.
Исходные изображения значка взяты из Komet.

Для проверки интерфейса с вымышленными чатами и 80 сообщениями на чат:
`./w10m/tools/preview.ps1 -Fixture`. Это отдельный пакет для ПК; данные
не отправляются на сервер. Для обычного предпросмотра запустите без `-Fixture`.

Исходники и лицензии аудиодекодера: [Opus](https://opus-codec.org/downloads/),
[libogg](https://xiph.org/ogg/). Системные HTTP/TLS используются вместо opusurl.

Фоновый механизм следует [документации Microsoft о socket broker](https://learn.microsoft.com/en-us/windows/uwp/networking/network-communications-in-the-background)
и [in-process background tasks](https://learn.microsoft.com/en-us/windows/uwp/launch-resume/create-and-register-an-inproc-background-task).
Декодер изображений: [libwebp](https://developers.google.com/speed/webp/docs/api).
